注意：同一个大领域可有多层 owner；每个 `(capability, modality, provider/transport, medium, task, stage)` 仅有一个决策 authority。Camera 意图、图像文本序列化、provider 参数不是三个竞争的摄影创作者。

### 已确认的真实执行链

1. Director/approved canon 定边界；Specialized Asset、Camera、Lighting、Color、Blocking 各写其原件。
2. `CinematicShotSpec` 是时间/相机/表演的装配投影，不能重新设计。
3. 静态 `VisualPromptIR` 携带 task/world/subject/camera/lighting、source 与 current state；`compile_ir` 负责选取、优先级、scope、retained/omitted 与 seal。
4. `image_serializer.render_image` 是当前所有 STATIC 的共享 serializer，并非已有独立 GPT Image 2 专业提示 adapter。初始图是 target sections；edit 是 delta→preserve→target。
5. `image_route.select_frame_template` + `frame_request.compile_frame` 管当前 GPT Image 2 Comfy 参数、模板和 slot；submission gate 拒绝旧 Flux formal frame。这是本地明确默认，不由 fal endpoint 排名产生。
6. Host/MCP/预算/Media 层负责真实执行与完成。参考图、来源、审批和输出观察相互独立。

仍可读的 legacy prompt 分支不是新正式 dispatch 的第二 authority：`require_submission_ir` 要求 IR 并逐字核对 payload，旧无 IR snapshot 只能 replay。旧 Visual Medium 文档关于 enhancement 的叙述不能覆盖较新的 specialized authority gate；本轮依据源码辨明，而非把旧文档当现行默认。

### 本地验证强度

已在 `drama-mcp-service/.venv/bin/python` 中禁用 socket.connect/create_connection，运行现有六个 test modules：image_serializer、visual_prompt_ir、specialized_asset、professional_departments、hero_vidu_routes、route_image_inputs。结果 **127 passed / 9.08s**，见 [日志](evidence/local-offline-tests-retry.txt)。第一次用 drama-plugin venv 因缺 pytest 未启动测试，失败日志也保留；未安装任何依赖。

这些证据证明当前模块的契约和确定性行为。它们不证明 photography quality、caption ordering、肤色真实或 provider 相对效果。没有同范围本地实产对照，因此本轮不援引 Level 4 声称本地专业 heuristic 胜出；契约冲突按 Level 1/2，双方未验证的 prompt 偏好按 Level 5 裁决。
