# 3. TOOL-001 实施结果

`ToolDefinition` 当前稳定表达：

```text
code
domain
name
description
input_schema
output_schema
handler
```

实现要点：

- Tool schema 来源是 `tools/catalog.py` 显式声明的 Drama Domain Contract 类型，不读取 Mock/HTTP handler annotation。
- `tools/schemas.py` 使用 Pydantic `TypeAdapter(...).json_schema(by_alias=True)` 生成 schema。
- Input root 保持 Tool callable 的 snake_case 参数名；嵌套 Pydantic payload 使用既有 camelCase alias。
- `object_schema()` 合并/提升 `$defs`，保证嵌套 `$ref` 可从输入 schema 根解析。
- 每个 Input Schema 都包含 `type=object`、`properties`、`required`、`additionalProperties=false`。
- 可选参数不进入 required。例如 `asset.resolve_asset_hierarchy` 的 `scene_id/shot_id` 均可选；`generation.create_generation_plan.parameters` 可选。
- 所有 33 个 Tool 均有显式 output schema。Pydantic Model、`list[Model]`、Enum 和基础类型通过 TypeAdapter 转换。
- `ToolRegistry.register()` 拒绝缺失 object/required 输入约束或空 output schema 的 ToolDefinition。
- `ToolRegistry.describe(code)` 可直接向未来 Host/MCP adapter 暴露契约。

真实 `context.build_context` description 删减示例：

```json
{
  "code": "context.build_context",
  "description": "Build a DramaModelContext payload; the host owns insertion.",
  "input_schema": {
    "type": "object",
    "required": ["request"],
    "properties": {
      "request": {
        "title": "ContextBuildRequest",
        "type": "object",
        "required": ["scope", "resourceId", "purpose"]
      }
    }
  },
  "output_schema": {
    "title": "DramaModelContext",
    "type": "object"
  }
}
```

Mock 与全 HTTP Provider 分别构建 ToolRegistry 后，`describe()` 结果完全一致，证明 Provider 只决定 handler binding，不决定 schema。

# 5. CTX-002 实施结果

旧全局 `provider_mode` 已移除，没有保留双轨兼容。新配置为：

```yaml
providers:
  project: {mode: mock}
  asset: {mode: mock}
  history: {mode: mock}
  generation: {mode: mock}
  media: {mode: mock}
  context: {mode: local}
```

Project/Asset/History/Generation/Media 支持 `mock|http`；Context 支持 `local|http`。只有选择 HTTP 的 domain 才要求对应 `services.<domain>.base_url`。Concrete Provider 构造仍全部集中在 `DramaPlugin._initialize_providers()`，没有进入 Skill、Tool、ContextBuilder 或 Contract。

实际验证：

| Case | 配置 | 实际装配 | 结果 |
|---|---|---|---|
| A | 五域 mock + context local | 5×MockProvider + LocalContextProvider，0 HTTP client | PASS，Demo/七 Scope 可运行 |
| B | 五域 mock + context http | 5×MockProvider + RemoteContextProvider，1 HTTP client | PASS，Plugin 初始化成功 |
| C | project http；其余 mock；context local | HttpProjectProvider + 4×MockProvider + LocalContextProvider，1 HTTP client | PASS，独立选择成立 |

CASE B 不要求其他五域配置 HTTP endpoint；CASE C 的 LocalContextProvider 自然接收混合的领域 Provider Protocol，无 DI Framework。

# 6. SKILL-001 实施结果

新增 `SkillToolReferenceValidator`，在 DramaPlugin 完成 SkillRegistry 和 ToolRegistry 构建后、返回 Plugin 实例前执行。

校验内容：

- 遍历每个 Skill 的 `tools.preferred` 和 `tools.allowed`。
