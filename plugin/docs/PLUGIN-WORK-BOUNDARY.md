# Plugin / Work / Provider / Host Boundary

## Plugin Core owns
Historical film and drama methods, evidence and invention distinctions, source freshness,
causal and spatial reasoning, character-defining trait prioritization, screenplay and
runtime contracts, Director authority, partner/ensemble performance, editorial and music
capabilities, and provider-neutral execution requirements. Capabilities are available
when the approved dramatic scope needs them; their existence does not mandate a scene,
character archetype, climax, visual medium, score, runtime or ending.

## Work owns
Characters, relationships, events, dialogue, character arcs and beliefs, geographical
setting, historical period and region, art bible, visual-route choice, stylization,
scene and shot content, expected-runtime values, music cues and production decisions.
Attested historical causality and attribution remain evidence-bound. Peripheral or
fictional viewpoints and invented personal relationships are allowed when labeled as
invention and not presented as changes to attested facts. Character-defining traits
come from the approved profile and take priority over generic attractiveness.

A new ProjectVisualRoutes declaration requires explicit visual_route and enabled_routes.
There is no implicit live-action or CG selection. Existing serialized explicit declarations
remain readable; an old asset without a route is not evidence of a newly chosen route.

## Provider owns
Concrete model behavior, supported inputs, API and output constraints, execution
parameters, cost and qualification evidence. Provider-specific graph syntax belongs
in adapters. Adapter limitations are not universal creative requirements. Qualification
and authorization are separate; a supported route is not permission to generate.

## Host owns
Orchestration, environment, credentials, filesystem/UI integration, transport selection
and authorization. Core skills consume source-bound intent and sealed execution identity.
Existing MCP-only adapters retain their transport checks; a transport-neutral creative
method does not imply an unimplemented alternative transport or permit silent fallback.
Casting EXECUTE expresses intent; MCP is retained only as a legacy caller alias.

## Examples and tests
NON_NORMATIVE_EXAMPLE = true. NON_NORMATIVE = true. RUNTIME_DEFAULT = false.
Examples, tests, integration fixtures and archived audits are not production prompt roots.
The SkillRegistry reads declared skill.yaml and SKILL.md, then a Host may follow explicit
method references. It does not enumerate examples/tests as context.

Default mock composition is empty. A developer may explicitly supply mock_data to load
an isolated fixture. Mock research never constitutes historical verification. Production
must obtain source evidence from the configured, qualified data/research integration.
Archived integration harnesses may perform writes: isolation is not permission to run them.

## Review boundary
No cross-work audit may silently rewrite formal Work data. Structural tests prove
contract and loader behavior, not artistic quality or the behavior of an unobserved
Host model prompt. New creative policy requires evidence of historical-film generality;
otherwise retain it in Work assets or clearly isolated examples.
