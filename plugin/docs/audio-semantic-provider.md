# Optional audio semantic observation

`ProviderBundle.audio_semantic` implements the generic `AudioSemanticProvider.observe_audio(AudioSemanticInput)` boundary. The explicit Host step is `hosts.audio_semantic.observe_audio`; it does not belong to Media storage, voice generation, or creative methods. Disabled mode creates no observer client and does not require a credential. No new Skill or MCP Tool is registered.

The first implementation is BailianQwenOmniAudioSemanticProvider under providers/http, reusing httpx. The SDK is not a project dependency, so no OpenAI or DashScope package is added. Fish role dubbing remains speech generation; semantic observation uses a separate client/configuration/lifecycle. Model selection applies only to observation; there is no fallback or change to video routes.

Load the selected component env file through the existing scripts/load-env.sh. Entries are documented in audio-semantic.env.example. Mode defaults off. Enabling bailian_qwen_omni requires the plugin-specific API_KEY and HTTPS BASE_URL. Endpoint is externally supplied, with no region/workspace guess. Model defaults qwen3.8-omni-flash; reasoning none; multichannel false. Provider options are overridable. No DASHSCOPE_API_KEY fallback. Keys use SecretStr, are excluded from serialized config and repr, and are not included in receipts. Config errors suppress validation-input traces; provider raw/error text is redacted before retention.

The adapter sends local PCM WAV as a Base64 data URI with input_audio/format=wav via Chat Completions, stream=true, modalities=[text]. No audio output, public file upload, search tool, response_format or json_schema is requested. It locally parses and validates six generic audio event layers in the existing adaptive-direction contract module. Invalid JSON, missing fields, invalid timestamps/enums/anonymous-speaker hints fail AUDIO_SEMANTIC_RESPONSE_INVALID, preserving safe raw text. Format repair is disabled (zero requests, within the allowed maximum of one). Bad semantic output is never retried to seek a better answer.

At most two transient retries follow timeout/network reset/429/5xx. Receipts count each attempted semantic request, carry request IDs/usage if available and preserve safe error categories. A timeout may have reached the server: retry counts are not a promise of free requests. There is no implicit region/model/provider fallback. Redirects are disabled.

Encoded data must be strictly below 10,000,000 bytes (conservative decimal 10MB). The source window carries sourceMediaHash, sourceAudioHash, absolute sourceStart/sourceEnd and mediaDuration. Oversized inputs return AUDIO_INPUT_TOO_LARGE and a suggested smaller duration, before HTTP submission. The caller splits with the existing ffmpeg pipeline and reuses the same media hash plus absolute offsets for each invocation; no new transcoder or automatic multi-call expansion is installed. WAV duration and file hash are verified. Provider relative times are shifted to absolute time and range-validated.

AudioSemanticEvent/AudioSemanticObservation are provider-neutral timed facets in the existing observation contract module, not a Qwen result schema. Returned claims and raw text are not creative authority. Host alignment uses the existing approved visual receipts; it labels audio candidates separately and leaves adoptedAudioFacts empty. Actual ObservedMaterialEvidence(method=AUDIO) conversion requires a genuine user factuality review pin. Host must authenticate that review: a supplied pin is not by itself proof of approval. No current-film observation is authorized by this provider integration.

Official interface verified on 2026-09-19: [Bailian Qwen-Omni](https://help.aliyun.com/zh/model-studio/qwen-omni). Model and multimodal request support, Base64 bound and channel/reasoning options come from that API reference, not from the current Work. Runtime quality must still be attested on actual audio.
