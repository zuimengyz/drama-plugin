# 9. Provider 引用关系审计

1. `providers/base/interfaces.py` 实际定义 6 个 `typing.Protocol`：Project、Asset、History、Generation、Media、Context。
2. Mock 和 HTTP 类没有显式继承 Protocol，而是采用 Python structural typing；方法集合审计对 6 组均得到 `mock_missing=[]`、`http_missing=[]`，mypy 严格模式也通过。
3. `ContextBuilder` 构造参数是 `ContextProvider`，Local/Remote 均提供 `build_context` 与 `refresh_context`。
4. Tool catalog 参数是各领域 Protocol，实际 Tool handler 是注入 Provider 的 bound async method。
5. Local Context 只依赖 Project/Asset/History/Generation Protocol；不依赖 Mock/HTTP concrete class。
6. Provider 选择集中在 `DramaPlugin._initialize_providers()`：mock 模式装配 Mock + LocalContext；http 模式装配 HTTP + RemoteContext。
7. concrete construction 搜索没有散落到 Skill、Tool、ContextBuilder 或 contracts。

Q3 结论：**Provider abstraction 在类型和调用依赖层真正隔离了 Mock/HTTP，并为 future MCP 保留了 structural Protocol 扩展点；上层 concrete 引用仅存在于 composition root。** 但 Remote Context 的配置选择仍与全局 provider mode 耦合，见 CTX-002。

### TOOL-001 ToolRegistry 尚不是完整稳定的 Tool Contract Registry

### CTX-001 Context Patch change value 与完整 Context 的 wire alias 不一致

- 严重程度：MEDIUM
- 文件：`src/drama_plugin/context/local.py`
- 代码位置：81-100，特别是 83-84 的 `model_dump(mode="json")`
- 分类：A. 明确缺陷
- 现状：完整 Context 对外序列化可使用 camelCase alias；Local refresh diff 使用未启用 `by_alias=True` 的 dict，并把该 dict 放入 `ContextChange.value: Any`。外层 patch 即使按 alias 序列化，也不会转换 Any 内部 dict。
- 为什么是问题：审计实测 patch 外层是 `baseVersion/newVersion`，但 replacement value 内出现 `plan_id/generation_target/workflow_code`。将它应用到 camelCase 完整 payload 会形成混合命名，跨语言 Java/Host 尤其容易出错。
- 是否违反第一阶段设计：违反 Full Context 与 Context Patch 应遵守同一 DramaModelContext Contract 的一致性要求；不涉及 Agent lifecycle 越界。
- 建议处理阶段：Host Integration 或 Java Remote Context 接入前；先冻结 patch path/value 的 canonical wire representation。

### CTX-002 Remote Context 的选择与全部 HTTP Provider 全局耦合

- 严重程度：MEDIUM
- 文件：`src/drama_plugin/plugin.py`
- 代码位置：90-121
- 分类：B. 架构偏差
- 现状：`provider_mode` 只有 mock/http。LocalContextProvider 只在 mock 分支，RemoteContextProvider 只在 http 分支；http 分支强制 project/asset/history/generation/media/context 六个 base_url 全部存在。

- 是否违反第一阶段设计：部分偏离“LocalContextProvider 可替换为 RemoteContextProvider”的独立可替换目标；不影响当前纯 Mock 或全 HTTP 两种模式。
- 建议处理阶段：Java Remote Context Service 接入前；支持按 domain 选择 provider 或单独 `context.provider_mode`，无需发展成复杂插件系统。
