# Character Embodiment contract

Driver owns character identity; Embodiment owns source-derived observable existence logic; Art owns the visible asset. No canonical image is required. No actor likeness, fixed costume, anatomy template or provider prompt belongs in this layer.

`character-package-v1` remains byte-compatible and has no embodiment file. `character-package-v2` includes a required `embodiment.yaml`; package version and schema version are independent. Create a new package version, never rewrite a pinned version. NONE/ARCHETYPE are explicit depth decisions, not synthesized template characters. FULL records all nine dimensions and 3–7 theses; LIGHTWEIGHT can record fewer. Technical validity does not approve a design.

`contracts.character_embodiment.CharacterEmbodiment` defines source pointers/hashes, interpretation, observableEvidence, conditions and avoid; theses reference rule IDs. Provenance locks source package/ref/version/checksum, Work/revision, directive hash/ref, Host, date and derived sections. Source validation checks the exact prior package and preserves its nine design sections, including route envelopes. Source cycles, changed pins, malformed/undeclared files and checksum mismatches fail. Archived profiles never participate.

Use `characters.authoring.create_character_version` under CharacterDesignAuthorization (Character External Driver + explicit directive). Embodiment authoring uses this existing ownership entry; downstream consumers cannot obtain a writer from CharacterRepository. Authoring validates source and review findings before creating a directory. Existing versions are immutable. Reader snapshots are detached, not an OS-level security boundary against arbitrary filesystem writes.

`CharacterRepository.resolve_character_package` returns `package.embodiment` for schema v2 and preserves the old v1 payload shape. `characters.embodiment.embodiment_handoff` requires authored, reviewed embodiment and an explicitly available route, returns no comparison material for production, and never changes assets. `verify_downstream_embodiment` rejects changed proposed snapshots. Missing embodiment raises EMBODIMENT_NOT_AUTHORED, without an archive or memory fallback. The repository still permits DESIGN_REVIEW for legacy packages; CASTING/PRODUCTION status gates are unchanged.

Art consumes core + embodiment + route and designs face, proportions and visible assets. Costume/Prop departments retain detailed equipment ownership. Casting consumes Art + embodiment and evaluates candidates, without discovering character meaning. Expression provides generic amplification grammar, never character-specific meaning; CG and live-action envelopes are separate and missing routes do not inherit. Director selects an existing tendency for the scene. Action uses screenplay + Director intent + embodiment + actionSignature; Performance realizes conditional state without changing identity. All are read-only. Missing meaning returns CHARACTER_CORE_INSUFFICIENT; missing existence logic returns to Embodiment Authoring.

`review_findings()` yields DISTINCTIVENESS_INSUFFICIENT for missing/interchangeable counterfactual evidence, and EMBODIMENT_FAILS_BODY_INDEPENDENCE when surviving rules require removed supports. The checker validates recorded Host judgments and reference integrity; it does not infer literary uniqueness or recognize pictures. Record falsifiable observation tests and leave artistic approval to the user.
