# Director creative runtime

Reuse DirectorWorkspace.expected_runtime and DirectorDepartmentPacket.expected_runtime. DirectorRuntimeEstimate and SceneRuntimeBudget are nested values, with no independent schema lifecycle, tool, DB or endpoint. Older workspaces remain readable and omit the absent facet on serialization. New full screenplay artifacts carry a source-bound workspace with the facet. The unique complete_production_book gate blocks missing, stale or incomplete runtime estimates; department readiness alone does not grant Book completion.

Each scene carries its current source pin, purpose, sequence/act, dialogue/action/silent-performance/transition seconds, expected target/range and a concrete estimate basis. The first four categories are mutually exclusive accounting buckets: concurrent dialogue/action is assigned to its primary dramatic function, not double counted. Music is an independent overlay split into music-bearing, intentional no-music and undecided seconds. Undecided is allowed during upstream revision and cannot masquerade as an approved Cue. All values are finite and nonnegative; ranges and whole-film sums are checked. review_runtime derives sequence/act totals, preserving uncertainty. No media is produced and no actual duration is claimed.

Historical provenance, character arcs, action geography and originality already fit the screenplay Bible/Scene open content; reuse those artifacts. H denotes attestation, I reasonable inference and D invention when a work chooses that notation, not a universal claim that a narrative source is objectively verified. No default film length, character, historical epoch, tragedy, score density or visual route is introduced.

Generality audit also removes historical-person wording from generic casting copy and cue IDs from adapter output filenames. Music translation artifacts now explicitly declare protectedPerformanceTexts (an empty list is valid only when the host declares none); supplied text is checked before execution and its fingerprint enters the mapping trace. Specific poems belong in Work data or integration examples, not global constants. Existing stored candidates/traces are never renamed or rewritten. This is lexical protection, not a semantic lyric classifier; source exclusion refs and exact reviewed ComposerBrief checks remain mandatory.
