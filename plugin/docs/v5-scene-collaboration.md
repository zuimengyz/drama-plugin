# V5 scene collaboration: existing owners, shared context

The Director method is [scene collaboration](../skills/director/references/scene-collaboration.md).
Host selects an encounter-level intention and reconciles Blocking, Camera and
Editorial proposals before formal coverage is locked. Editorial may advise on
provisional coverage; formal department ownership is unchanged. Existing
`screenplay.support_packet`, `retain_support`, `decide` and `shot_handoff` retain
actual contributions and selection. A single Host's offline exercise is not four
independent authors, a paid model run or formal adoption.

## Executed path

`FormalDirectionAuthor` loads the scene collaboration method in `DIRECTION_CRAFT`
for both treatment and formal direction. It participates in the execution
fingerprint. `FilmCapabilities.create_unit` derives a same-scene ordered semantic
coverage view from the exact stored `FilmDirection` and pins its Canon/Direction
references beside the selected scene in the existing screenplay artifact store.
`CreativeEngineCapabilities._request` reads that immutable child input. `author_payload`
passes `hostScreenplay.sceneDirection` to the real professional author, withholding
internal source refs. The requested ACTION/Camera/Editorial Skills are loaded by
that author; Blocking continues through the existing ACTION capability.

This is context, not a new creative entity, automatic debate or Runtime author.
Formal professional originals still map through `ShotAssembler`, operation
selection and `PromptCompiler`. No scene-context blob is added to the Provider
wire. Current entry/action/exit, Camera execution facts and scoped Editorial
requirements carry the selected meaning. The compiler does not repair a bad cut.

The snapshot contains semantic ordered coverage, not every department original.
Host retains/reconciles those through existing support and professional references.
If the chosen solution changes a neighboring shot, prepare a revised parent and
new affected child identities. Old children retain their old input for recovery;
reusing an operation identity for changed creative content remains rejected.
An isolated local-shot caller without a parent film must supply the relevant
selected scene context explicitly; this change does not scan mutable history.

## Boundaries and evidence

An Action phase's initial START is local to the shot. Native `boundary_for` uses
`DirectedShot.transition` when moving between film units; preview/execution binds
that relation with predecessor evidence through existing `MediaBoundary`.
FRAME_REFERENCE chooses a media role and cannot determine the editorial strategy.
A new judgment field must not be treated as proof of a meaningful match.

The V5 tests use retained historical scene text and Host-prepared proposals. They
exercise real selection/storage, native child creation, the intercepted text
request envelope, professional projection, assembly and Provider preview. No
network is permitted; previews are unadmitted. Passing them proves data delivery
and isolation, not independent model reasoning, performed timing, picture continuity,
valid live asset URLs, production admission or heard sound continuity. Actual media
review remains necessary after an authorized creative/production run.
