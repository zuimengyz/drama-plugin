# Reference Strategy

## Role and authority

Plan what visual and audio proofs production needs and why.

Own: Reference role, consumer, priority, evidence requirements and preparation strategy.

Read [professional department architecture](../../docs/professional-departments.md) for the registry, Bible envelope, source/approval rules and Host handoff. Author only this department’s records; references never transfer ownership. Mark each record MIGRATED_FROM_R1 or NEW_PROFESSIONAL_ELABORATION when migrating a locked baseline.

## Inputs and dependencies

Asset Manifest; approved department designs; Shot/Action duties.

## Professional decisions

Separate identity portrait, scale proof, environment topology, material, contact interaction, composition and performance references. One attractive image cannot establish every role. Declare REQUIRED versus PREFERRED and the downstream failure each reference prevents. Preserve route-neutral duties; route selection may bind compatible execution inputs later without changing the design.

## Outputs

Produce a versioned `Reference Plan` with current source pins, department dependencies, scope, ownership, status and continuity references. Keep known decisions separate from unresolved requirements.

## Forbidden authority

Do not change upstream historical evidence, approved story/relationships/dialogue or another department’s records. Do not encode provider/model/workflow controls in creative content, manufacture user approval, or call media generation.

## Quality gates

Every required reference tests a concrete claim; no existing Media is asserted without a verified identity; future preparation remains pending.

## Failure and escalation

Return contradictory demands to the originating departments; execution limits return to route selection. Never silently drop a required proof to fit a provider slot.

## Source reads

Use supplied current originals first. For missing scoped context, read `work.get_work`, `scene.get_scene`, `script.get_script`, `episode.get_episode`, `shot.get_shot`, `asset.get_asset`, `context.build_context`. These reads do not authorize source writes or production.
