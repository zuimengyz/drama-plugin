# Meaning-preserving prompt compression

Use when the Host/user asks to reduce prompt length. This is expression review,
not a new creative owner, compiler, Runtime gate or production authorization.

## Preserve the baseline

Retain the exact full native compiled prompt, its character-count convention,
source/package/final-text fingerprints and selected reference ordinals/roles/hashes.
Do not overwrite it. Keep original, deduplicated and compact candidates distinct.
Read every original clause; upstream summaries cannot substitute for this baseline.
If any source or binding changes, retain a newly compiled full baseline and review
the compression again. Do not silently reuse an old map.

## Two bounded transformations

First merge repeated meanings, retaining every distinct condition and scope. Map
each removed clause to the exact surviving clause(s); similarity of wording is
not sufficient. Preserve useful reinforcement for a demonstrated material risk.
Then shorten phrasing and combine compatible clauses without adding interpretation.
Explicit actor names, object identity, support/release, causal triggers, ordering,
negation, exclusivity, spatial vectors, gaze/listener tasks, start/end states and
reference exclusions survive. Exact approved dialogue survives verbatim.

Keep entry-only conditions separate from invariants and end states. A carried
object cannot lose its support transfer; a response cannot precede its stimulus.
Retain the current reference ordinal and permitted inheritance; broad style or
continuity labels cannot replace scoped exclusions. Keep camera motion separate
from actor motion, and intended focus/light changes separate from stable relations.
Avoid cryptic abbreviation and pronouns with competing antecedents. Do not delete
negative constraints merely because positive prose sounds similar.

Preserve the [shot-context reading](../SKILL.md#shot-context-in-the-final-prompt)
as at most two concise paragraphs in the final model text. Present circumstances,
relationships and expressive intent are distinct meanings, not disposable duplicates
of an action list. Merge repeated explanations while retaining their audiovisual
consequence; prior/future events remain context, never added shot action. This
uses the same source mapping and Host reread, without an extra compression stage.

## Bidirectional Host review

For each original semantic unit record its source span, candidate span(s),
transformation and preservation of actor, timing, condition, scope and consequence.
Split dense clauses where one row would hide a missing relation. Then read the
whole candidate back against the original for invented meaning, altered emphasis,
changed ordering, overbroad prohibitions and contradictions across sections.
Distinguish inherited ambiguities from compression-introduced ones; do not silently
repair the former while claiming equivalence. Return unresolved changes to the
original owner; restore words when equivalence is uncertain.

Counts, string matches and complete mapping links are bookkeeping, not semantic
proof. Name the Host review and its limits; model adherence remains untested.
Choose the shortest sufficiently clear candidate only after this review, not by
percentage reduction. A provider recommendation such as 500 characters is not a
hard limit; never truncate or submit automatically. A true hard capability limit
requires a separate source-bound decision, not hidden semantic loss.

## Boundary to later execution

The native Target compiler supports a pinned `PromptExpression` through
`GenerationTask.prompt_expression_ref`. Compile the complete baseline first;
retain its exact final artifact, task fingerprint, input references and text hash.
The Host supplies the reviewed expression and source-to-target span mapping as
an immutable expression artifact, with review basis and excluded local labels.
Compile the expression task through the same compiler, never by replacing text
inside a sealed request. Each expression compile first recompiles the full native
baseline; source/task/policy or input changes must invalidate the old expression.

Keep baseline coverage separate from transformed coverage. `HOST_MAPPED` records
Host-reviewed paraphrase spans; it is not verbatim `TEXT_COVERED` or automatic
semantic proof. The expression retains precise multi-span judgments, while the
coverage span may bound them for the consuming fact. Retain both final artifacts,
the expression, audio plan and preparation in the existing generation store.
Check the actual final wire text, parameters and reference order/bytes after
compilation. No runtime run, rights decision, spending or submission follows
from expression retention alone. If a consumer lacks this support, keep the
candidate offline; do not create a text-replacement fallback.

## Remove local bookkeeping without losing meaning

After retaining the complete original, replace local shot/task/version labels and
adoption/provenance language in the expression candidate. Map each reference to
visible target facts or an actually supplied image/video ordinal with scoped duty.
When no delivered evidence defines a relation, state the existing authored relation
explicitly or mark it unresolved for Host review; never invent missing geometry.
Do not substitute an equally unavailable “previous shot” reference and call it
resolved. Preserve source identifiers in the external comparison log, never in
the model prose. Inspect compiler-generated prefixes as well as the compact body.
A lexical scan supports but cannot replace the Host's referent-resolution review.
Keep intended dialogue, on-screen text, defined actor aliases and supported input
reference tokens intact. These rules do not authorize editing a sealed request.
